# 習慣化バトルパス 実装タスク分解

## 1. 実装方針

- MVP は「個人利用できる Web アプリ」を優先する。
- まずはデータの永続化、認証、基本 CRUD を固め、その後にレベル・報酬・シーズン処理を乗せる。
- 画面はあとから増やせるように、ドメインモデルを先に整理する。

## 2. 実装フェーズ

### フェーズ 1: 基盤構築

1. プロジェクト初期化
   - フロントエンド / バックエンドの構成を決める。
   - ルーティング、状態管理、UI 基盤を整える。
2. 認証基盤の実装
   - 外部アカウントログインを導入する。
   - ログイン後のセッション維持を実装する。
3. データ保存基盤の実装
   - ユーザー、タスク、報酬、レベル、シーズン情報の保存先を作る。
   - 複数端末同期を前提とした取得・更新 API を用意する。
4. 共通 UI の実装
   - ヘッダー、タブ、モーダル、ボタン、バッジなどの共通部品を作る。

### フェーズ 2: ドメインモデル定義

1. タスクモデルの定義
   - 種別、名前、説明、回数条件、完了状態、進捗、経験値候補を定義する。
2. テンプレートモデルの定義
   - タスクテンプレートと既存タスク流用の両方を扱える形にする。
3. レベルモデルの定義
   - 通算レベルとシーズン内レベルを分離する。
4. 報酬モデルの定義
   - 通算報酬とシーズン報酬を分離する。
5. シーズンモデルの定義
   - シーズン開始日、終了日、更新状態、未確認状態を管理する。
6. 経験値候補モデルの定義
   - デイリー、ウィークリー、シーズンで別管理する。

### フェーズ 3: タスク管理機能

1. タスク一覧画面の実装
   - デイリー、ウィークリー、シーズンのタブを切り替えられるようにする。
   - 完了済みタスクを薄く表示する。
2. タスク作成画面の実装
   - 新規作成、テンプレート複製、既存タスク複製を選べるようにする。
   - タスク種別に応じて経験値候補を切り替える。
3. タスク編集画面の実装
   - 名前、説明、回数条件、報酬候補を編集できるようにする。
4. タスク詳細画面の実装
   - 進捗、完了状態、報酬候補、複製導線を表示する。
5. タスク削除機能の実装
   - 誤操作を避ける確認ダイアログを付ける。

### フェーズ 4: 回数タスクの進捗管理

1. カウントアップ機能の実装
   - ボタンを押すたびに回数を増やす。
2. カウントダウン機能の実装
   - 増やすボタンより目立たない UI で減算できるようにする。
3. 完了判定の実装
   - 目標回数に到達したら完了ボタンを出す。
4. 完了後の固定表示
   - 同じ周期中は未完了に戻せないようにする。
5. 再挑戦導線の実装
   - 必要なら複製で新しいタスクを作成できるようにする。

### フェーズ 5: レベル・報酬機能

1. 経験値加算の実装
   - タスク完了や条件達成で経験値を加算する。
2. 通算レベルの実装
   - リセットしない累積レベルとして扱う。
3. シーズン内レベルの実装
   - シーズンごとにリセットするレベルとして扱う。
4. 報酬到達判定の実装
   - 通算レベルとシーズン内レベルで別々に判定する。
5. 手動受け取り機能の実装
   - レベル到達後にユーザーが報酬を受け取る。
6. 報酬一覧画面の実装
   - 通算報酬とシーズン報酬を分けて表示する。

### フェーズ 6: シーズン更新処理

1. シーズン切り替えロジックの実装
   - 2 ヵ月ごとに自動更新する。
2. シーズン内レベルのリセット処理
   - 新シーズン開始時にリセットする。
3. 未確認バッジの実装
   - ウィークリー・シーズンのタブに更新通知を出す。
4. 初回表示時のバッジ消去
   - 各タブを最初に開いたタイミングで未確認状態を消す。
5. 更新内容の説明表示
   - タブ上部に簡単な説明を表示する。

### フェーズ 7: 経験値候補管理

1. 初期候補の設定
   - デイリー、ウィークリー、シーズンに 3 個ずつ、合計 9 個を用意する。
2. 候補一覧の表示
   - タスク作成時にドロップダウンで選べるようにする。
3. 詳細設定画面の実装
   - 候補の追加、削除、並び替えを行えるようにする。
4. 候補の保存処理
   - 種別ごとに別管理で保存する。

### フェーズ 8: 履歴・仕上げ

1. 履歴画面の実装
   - 完了済みタスクを確認できるようにする。
2. 全体の状態同期確認
   - 複数端末で同じ表示になるか検証する。
3. モバイル最適化
   - タップしやすさ、一覧の見やすさを調整する。
4. 誤操作対策の見直し
   - 完了、削除、減算の UI を再確認する。
5. 最低限のテスト追加
   - タスク完了、レベル加算、シーズン更新、報酬受け取りを確認する。
6. 破壊的操作の確認 UI 横展開
   - 削除・リセット・取り消し不能操作で共通確認ダイアログを利用する。
   - 文言、ボタン順序、スタイルを統一し、独自 `window.confirm` 実装を排除する。

## 3. 優先順位

### 優先度高

- 認証
- データ保存
- タスク CRUD
- 回数タスクの進捗管理
- レベル管理
- シーズン更新

### 優先度中

- 報酬管理
- 経験値候補編集
- 未確認バッジ
- 履歴画面

### 優先度低

- 見た目の細かな改善
- 統計表示
- 通知機能
- テーマ変更

## 4. 依存関係

- 認証が先に必要。
- データ保存基盤がないとタスク管理は実装しにくい。
- タスクモデルがないと進捗やレベルも定義しにくい。
- シーズン処理はレベルとタスクの状態管理ができてから実装する。
- 経験値候補の編集は、タスク作成画面と接続してから完成する。
- 共通確認 UI の横展開は、各画面の削除/リセット導線が揃ってから進めると効率が良い。
